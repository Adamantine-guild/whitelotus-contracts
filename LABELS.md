# Issue Labels

This document describes the labels used in this repository for GrantFox contribution workflows.

## Contribution Type Labels

- **good first issue**: Issues suitable for new contributors. These are well-scoped, have clear acceptance criteria, and include implementation guidance.
- **help wanted**: Issues that need community help but may require more experience.
- **bug**: Reports of defects or unexpected behavior in smart contracts.
- **feature**: Requests for new smart contract functionality.
- **enhancement**: Improvements to existing smart contract functionality.
- **documentation**: Issues related to documentation, NatSpec comments, or guides.

## Priority Labels

- **priority: low**: Nice to have, but not urgent.
- **priority: medium**: Important but can be scheduled.
- **priority: high**: Urgent, should be addressed soon (especially security issues).

## Component Labels

- **GrantRound**: Issues related to the GrantRound contract.
- **GrantRoundFactory**: Issues related to the GrantRoundFactory contract.
- **tests**: Issues related to test coverage or test infrastructure.
- **deployment**: Issues related to deployment scripts or configuration.

## Security Labels

- **security**: Security vulnerabilities or security-related improvements.
- **access-control**: Issues related to permission and access control mechanisms.
- **reentrancy**: Issues related to reentrancy protection.

## Status Labels

- **status: blocked**: Issue is blocked by another issue or external dependency.
- **status: in progress**: Issue is currently being worked on.
- **status: ready for review**: PR is ready for maintainer review.
- **status: needs info**: More information is needed to proceed.

## GrantFox Campaign Labels

Maintainers use these labels to identify campaign-ready tasks:

- **campaign-ready**: Issue is ready for GrantFox campaign with clear acceptance criteria, estimated difficulty, and testing requirements.

## Label Usage Guidelines

- Use **good first issue** for tasks that can be completed in 1-4 hours by a new contributor
- Use **help wanted** for tasks that may require more Solidity experience or domain knowledge
- Always include a priority label for issues and PRs
- Use component labels to help contributors find relevant issues
- Campaign-ready issues should have detailed descriptions and acceptance criteria
- Security issues should be reported privately via email (see SECURITY.md)
